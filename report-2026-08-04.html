Where Things Went Wrong

2+ incidents · high severity

Parallel-session / subagent scope collisions

Background and subagent sessions edited the same branch as their parent, reverting live work and committing out of scope. Rare but expensive — they undo good work silently.

  • "Immediate hard stop: do not run any more git commands… The parent session is actively modifying the same branch and your continued activity reverted its test fix."
  • "Your commit was made after an explicit stop and is out of scope… Revert exactly commit 3f7ae8d4…"

  • "Preflight: confirm LinkedIn internal network is reachable (corp wifi OR GlobalProtect VPN)…"

📝 Suggested copilot-instructions.md additions

Each snippet is derived from a friction pattern above. Check the ones you want and hit "Copy All Checked".

Subagent branch isolation
## Subagents — branch safety Never let a subagent or background session run git write commands (commit, push, checkout, restore, edit) on a branch a parent session is actively editing. Before any subagent does git work, it must confirm it is on its own worktree/branch. If a stop instruction arrives mid-task, halt immediately without a final commit.
Why: 2 incidents this week where a background session reverted a parent's test fix and committed out of scope (3f7ae8d had to be reverted).
Prototype design-fidelity defaults
## Prototype visual defaults When building prototype cards/modules: top-align content inside the card, keep the module vertically centered on the page, and use the chat-input border token for card strokes (not a heavier border). Tag/label text matches timestamp text size. Hide entry points for artifacts that are already generated.
Why: 4+ re-prompts on FY27/play-mvp prototypes correcting these exact defaults after the first pass.
Reusable VPN preflight
## Unattended runs — network preflight For any unattended/scheduled job that touches LinkedIn internal resources, call ~/.copilot/scripts/vpn-preflight.sh first (create it if missing). If it fails, write a dated skip-flag and exit 0 — never proceed and never half-run. Do not re-implement the curl check inline in each prompt.
Why: 42 unattended sessions each re-paste bespoke VPN preflight boilerplate; centralizing it removes silent off-VPN no-ops.
Batch-prompt templating
## Repeated single-shot analyses When the same rubric is applied across a list of items (e.g. tickers), do not hand-launch one session per item. Read the shared rubric from a template file and the item list from a manifest, and iterate. Keep per-item output files named by the item key.
Why: 164 near-identical investment-tool sessions re-pasted the same investor rubric per ticker.

New Ways to Use Copilot CLI

Templated batch driver for the ticker sweep

164 of 337 sessions were one-shot ticker analyses. Replace the hand-launch loop with a single driver that reads a manifest + shared rubric and writes one report per ticker — turning a morning of copy-paste into one command.

In subsscsl/investment-tool: create tickers.txt (one symbol per line) and rubric.md (the shared Singapore-investor rubric). Then write a script that, for each ticker, runs the analysis using rubric.md as the system context and writes reports/<TICKER>.md. Skip tickers whose report already exists so it's resumable.

Consolidate the cron fleet under one scheduled-run contract

You run brain-refresh, ai-news-digest, daily skill-fix, and Granola filing as separate unattended jobs, each with its own preflight. Standardize them on one wrapper that does VPN preflight → dedup flag → run → Slack summary, so a new job is 10 lines not 100.

Create ~/.copilot/scripts/unattended-run.sh that takes a job name + a prompt file, runs VPN preflight, checks a per-job dated done-flag in ~/.copilot/state/<job>/, runs the prompt headless if not already done, writes the flag, and posts a one-line Slack summary. Then migrate brain-refresh and ai-news-digest to call it.
