Copilot CLI Features to Try

Suggested copilot-instructions.md additions

Each snippet is derived from a friction pattern above. Check the ones you want and hit Copy All Checked.

When building interactive prototypes, persist UI state (active tab, panel/chat position, "intro-animation-seen" flag) to localStorage keyed by view. Restore it on mount so leaving and returning to a tab or reloading never replays intro animations or resets element positions.
Why: 2+ corrections in fy27-prospecting-agent — the intro animation replayed and the chat jumped back to the corner after tab navigation.
Before applying any toggle/reversal/directional edit (move X left→right, swap A/B, increase→decrease), first restate the intended END state in one sentence, then make the edit. If a previous attempt went the wrong way, describe what the wrong result looked like vs. the target before retrying.
Why: "no you did the opposite" plus four bare "try again" reprompts in a single session — directional ambiguity drove the loop.
When mocking a NEW SN surface or workspace, do not carry over the current production nav bar, tabs, or IA by default. Confirm the target information architecture (which tabs/sections exist in the new design) before building chrome. If unspecified, ask or infer from the mock — never default to today's shipping nav.
Why: "why are you still using today's SN nav bar… they don't match the new workspace."
For any headless/batch/orchestrator run (investment analysis, granola filing, digests), the final step must write a durable output artifact (file or committed summary) AND print a one-line PASS/SKIP/FAIL status naming the item processed. Never end a batch item silently — a run with no artifact is a failure, not a success.
Why: 94 automated sessions ended ≤2 turns with no summary; 101 logged zero turns — silent no-ops are indistinguishable from success.
After any visual/layout change to a running prototype, capture a screenshot of the actual rendered result and compare against the request before saying it's done. If a spatial property (position, size, alignment) was requested, assert it from the DOM/computed style rather than assuming the edit worked.
Why: repeated directional/visual corrections would be caught pre-emptively by a render check, collapsing the "try again" cycle.

Hooks worth adding at ~/.copilot/hooks/

A post-edit hook that greps changed prototype JS/TS for localStorage usage when the diff touches tab/panel/animation state, warning if a stateful component ships without persistence.

Why for you: your only recurring prototype-bug class this week was non-persisted state.

On session end for orchestrator repos (investment-tool, granola-memory), verify the expected output file exists; block/warn if a "completed" run left no artifact.

Why for you: 94 batch sessions ended with no summary — this closes the silent-skip gap directly.

Why for you: 33 lighthouse-web sessions, several in pr-autofix worktrees — catch failures locally.

New Ways to Use Copilot CLI

Turn the 199-run investment pipeline into one manifest-driven driver

You executed ~130+ near-identical ticker analyses as separate sessions. Collapse that into a single driver that reads a ticker manifest, fans out subagents (you already average 84 subagent calls/session in these), and writes one report per name — one command instead of 199 launches.

Build a headless driver script in investment-tool that reads tickers.txt (one symbol per line), and for each ticker runs my standard brutal-honesty equity analysis prompt as a background subagent with the fixed investor mandate (Singapore tax resident, 2% cap, 30yr horizon, MARR 15%). Write each result to reports/<TICKER>.md, skip tickers whose report already exists and is <7 days old, and print a PASS/SKIP/FAIL line per ticker at the end.

A screenshot-diff loop for prototype iteration

Your longest, highest-friction sessions were visual. Wire a tight capture-compare loop so the model self-checks layout changes with Playwright before handing back — this is where your "try again" tokens are going.

In fy27-prospecting-agent, set up a Playwright-based visual check I can invoke after any layout change: navigate to the prototype route, dismiss overlays, screenshot the target component, and assert the requested spatial property (position/size/alignment) from computed style. Report pass/fail with the actual values before telling me it's done, and always browser_close at the end.

Consolidate the daily digest orchestrators

granola-memory, ai-news-digest, and skill-fix each fire as separate unattended runs. A single morning "digest" driver that sequences them and posts one combined status would cut launches and give you one place to see failures.

Create a single scheduled "morning digest" workflow that runs, in order: granola-sync + file today's meetings, generate the AI-news digest, and run the daily skill-fix pass — each as its own subagent. Collect a one-line status from each and write a combined docs/morning-YYYY-MM-DD.md summary. If any step produces no artifact, mark it FAILED in the summary rather than skipping silently.
